# Open decisions and the defaults to use

Until the owner decides, use the default. Note in `NOTES.md` whenever a default shaped your work.

| 15 | What the Eraser does to the faces beside an edge | Decided (changed 2026-11-06) | As in SketchUp: erasing the edge between two faces **on one plane** merges them into one face (so it can be offset, pulled and so on). | 18 | Locking the Rotate tool's protractor | Decided | The protractor is a full circle. Rotate uses the same snaps as the other tools. Built with Edit Tools. |
| 19 | Perpendicular guides while drawing | Decided | Not wanted for now: only "Parallel to Edge" guides, as in the feel test. |
| 20 | What is greyed out in menus, the dock and search | Decided (a standing rule) | Only what is actually built, even partly, is active; everything else is greyed. Keep it true as the project grows: when a tool or command gets built, make it active in the same change. In code, the action registry takes the list of tools from `prism_tools::session::TOOLS`, so a tool is only pickable once the session runs it. |
| 21 | Selecting points with edges and faces | Decided | Points are the glue between edges and faces. Box select takes the points in the box with the edges and faces, and Select All and triple-click take every connected point, so nothing is left behind when the selection moves (moving an edge or face always moves its points too). Shift or Ctrl with a double or triple click adds or removes the face-and-edges or the connected set, without touching the rest of the selection. "Connected" also crosses faces, so a pocket comes with the box it is cut into. |
| 22 | Copying a group | Decided | Copies of a group are independent at once; editing one never changes another. Only component instances are linked to a shared definition. |
| 23 | Glue to and Cut opening | Decided | Not in the first Groups & Components chunk; they come later. When built, show a small visual sign when a component can glue to the face under it, and put a global on/off toggle for gluing in the right-click menu (the owner found SketchUp's gluing hard to predict). |
| 24 | Double-click to open a `.prism` file | Decided | Double-clicking a file opens it **in the Prism that is already running**, in a new tab (#27); only if Prism is not running does it start. A file that is already open switches to its tab. Files & Formats part 1 opens a file named on the command line and declares the type in the Mac `Info.plist`. The rest comes with tabs (Files & Formats part 3): macOS sends the file to the running app as an Apple event, which winit does not pass on, so Prism adds a small handler; on Windows a second start hands the file to the running Prism and quits. Registering `.prism` with Windows needs an installer (the packaging step). |
| 25 | 3MF and the 0BSD licence | Decided | Write 3MF ourselves with `zip` and `quick-xml` (MIT). The `threemf` crate (0BSD) is not used, and 0BSD stays off the licence list. |
| 26 | What Rotate turns with nothing selected | Decided | As in SketchUp: Rotate works on the selection, or with nothing selected on the item under the cursor alone (like Move), not the whole connected body. Rotating a face that is attached to other faces twists it, and the attached faces fold into flat pieces (triangles where needed). |
| 27 | Several documents at once | Decided | Tabs in one window, not a new copy of the program per file (the owner's old SketchUp is slow to start a new copy). Each tab has its own document, undo history, selection, camera, tool state and autosave journal. File > New and Open make a new tab; closing a tab asks "Save changes?" for that document. Built as Files & Formats part 3, with #24. **Look (owner's choice):** a compact strip of tabs (22 points) just under the menu bar, as wide as the viewport: not floating over the viewport, and not a dropdown. |
| 28 | Code signing for the native builds | Open | Ship unsigned until the packaging step, and say so in the release notes. Then decide: Apple Developer Program (USD 99 a year) for macOS notarisation, and Azure Artifact Signing (about USD 10 a month, US individuals; check that Guam qualifies) or an OV certificate (about USD 150–500 a year) for Windows. | 29 | Intersections of faces that pass through each other | Decided | Wherever two faces cross with no edge along the crossing, the system knows it, **whether or not the pieces are connected** (a shape pushed through another and still joined to it counts; the owner's example). Two things, as Edit Tools part 3 (after Files & Formats part 2). (1) **Inference** finds the crossings: a point where an edge goes through a face ("Intersection"), and the line where two faces cross, drawn as a dashed guide you can snap along, with its ends as points ("Face Intersection"). So you can trace one shape's outline onto another's faces. (2) **Edit > Intersect Faces** (with the model, with the selection) adds those crossing lines as real edges in one undo step, so the overlap can be erased or pushed through to make a tunnel. Planar faces use exact plane-plane intersection clipped to both faces; curved faces wait for the kernel. Model Health (PLAN 1.10) also lists faces that cross without an edge. |
| 30 | Faces on one plane after an edit | Decided (owner, 2026-11-08) | One rule for coplanar faces everywhere: after Push/Pull, Move, Rotate, Scale and copies, every plane holding a face the edit touched has its crossing edges split and its faces rebuilt as one set of regions, as drawing already does. Overlapping faces become one set of faces; where two faces meet back to back (a face pulled flush against another) both go, so the solids join; and an opening the edit left (where a new edge now closes it) gets a face. Push/Pull decides edge by edge: an edge whose other faces run along the push behind the face slides, so those faces stretch; every other edge gets a new wall. |
| 31 | Push/Pull on a solid | Decided (owner asked for one general rule, 2026-11-08) | **Where faces enclose space, Prism keeps the boundary of that space.** Push/Pull on a face of a closed solid is a boolean: pulling out adds the block the face sweeps through, pushing in removes it. After the pull, faces near the edit are cut where they cross, and each piece is kept only if the solid is on exactly one side of it, facing out (a piece facing in is turned round); an empty region gets a face where the solid is on one side only. This one rule removes walls left inside, joins blocks pulled into or flush against each other, swallows a smaller block, cuts a tunnel when a face is pushed out through the back, and closes the bottom of a post left floating. Faces that enclose nothing (a lone rectangle, an open box) keep the plain behaviour. Alt (new loop) keeps the original face on purpose. Move, Rotate and Scale do not cut solids (only the coplanar rule, #30, runs), so moving a box through another leaves crossings for Intersect Faces (#29). **Changed 2026-11-09 (owner): Push/Pull never passes through a face.** The face moves freely until it meets another face and stops there (letting go there merges them); a neighbour that leans over its path blocks it at once. So a pull now stops at a smaller block and joins it instead of swallowing it, and a face pushed out through the back stops flush with it (which still cuts the tunnel). Alt (new loop) is not limited. |
| 32 | Curves that are not lines or arcs, before NURBS | Decided (owner, 2026-11-09) | Until the NURBS kernel arrives (NURBS Spike, after Exact Curves), an operation that would make a curve Prism cannot store exactly (uneven Scale of a circle, a cylinder cut by a slanted plane, crossing cylinders, Follow Me along a freeform path) **falls back to fine straight segments marked approximate**. Model Health lists them, and NURBS can replace them later. Nothing is refused. **Built last** (owner, 2026-11-09): the fallback comes once the five exact parts are finished, not partway; until then those operations do what they do now. See `docs/research/exact-curves.md`. |
| 33 | Curved faces in the standard tools, and known gaps | Decided (owner, 2026-11-11) | **A new kind of geometry is not done until the standard tools work with it.** Exact Curves gets a part 6 before its tools become active: the segment fallback (#32), exact crossings of planes with cylinders, cones, spheres and tori, Intersect Faces, sticky crossings, and Push/Pull booleans and stops with curved faces (PLAN 6.0a). **Standing rule:** every chunk's known gaps are sorted at its end: each serious one gets a step in the plan (in that chunk or a named later one), not only a line in NOTES. |
| 34 | Bundled textures | Decided (owner, 2026-11-12) | **No textures are bundled.** The Materials window's built-in library is the plain colour palette (in code). Textures come only from images the user loads. (The default had been to bundle about 30 CC0 textures.) |
| 35 | Where a material and its texture placement live | Open (default used, 2026-11-11) | **Default:** materials are document-wide (one table shared by every group's model), with stable ids. A face side carries an optional material and, once textured, an optional placement (origin and axes in model space), which Move, Rotate and Scale transform with the face. A group or component instance carries an optional material, *drawn* on its Default faces (the nearest painted group wins), never copied onto them, as in SketchUp. Default placement on flat faces is anchored to the model's axes (u horizontal along the face, v up it; red and green on floors); curved faces use their exact (θ, s) coordinates (a cylinder and a cone unroll without stretch). |
| 36 | Materials through edits | Open (default used, 2026-11-11) | **Default:** pieces of a split face keep its material and placement; merged faces take the largest piece's; Push/Pull keeps the moved face's and makes new walls Default (as SketchUp); copies keep theirs; Follow Me's walls take the profile's; a reversed face swaps front and back. A property test guards it. |

| 40 | Bend / Twist / Taper (Shapes & Placement part 7): exact geometry or tolerance-fit | Decided (owner, 2026-11-24) | A flat face a deform touches cannot stay flat, so **it is refit as a NURBS surface within the model's tolerance**, the same way Fusion 360's Bend/Twist/Taper (and Loft's own surfaces) already work — CAD-style "accurate to tolerance," not infinite-precision (CLAUDE.md, "Rules that apply everywhere"). Never a triangle mesh. Built as a live `Feature` in the Inspector's stack (the same one Round and Chamfer already use), with a drag handle on the axis in the viewport (diegetic, per the owner's Hinge/Slide preference) and the existing measurement box for an exact typed value — no new island, since nothing here needs a value shown while nothing is being dragged. | 41 | Shell / Thicken: refuse or build with a warning | Decided (owner, 2026-11-26) | **Never refuse what can be built: build it and warn.** "Just give everything a warning, its frustrating when there is no other feedback with the tool, i can't even see which direction isn't going to work." | 42 | Tolerance: one fixed distance per document | Decided (owner, 2026-11-26; details accepted after the audit, `docs/TOLERANCE-AUDIT.md`) | **One fixed tolerance per document, not tied to the model's size**, the same in every group, stored in the file. **Default 0.01 mm (Standard)**; a document setting offers Fine 0.001 mm, Standard 0.01 mm, Coarse 0.1 mm, or a typed value (1e-9 m to 1 cm). **Every other threshold is derived from it**, including "parallel" and "coplanar": directions agree when they differ by less than the tolerance over the length involved, not by a fixed angle; fits to a tenth of the tolerance. **Graceful fallbacks:** an edge drawn shorter than the tolerance is drawn, with a warning and an offer of Fine; geometry too far from the origin for the numbers to hold the tolerance is warned of (Model Health); an older file whose smallest details the default would merge opens at a finer setting, and says so; making the setting coarser shows what would merge before it is applied. Work in five stages (the audit's section 5.5), each tested and released: (1) the tolerance stored in the document and used by every model; (2) the length-aware parallel test and the stray distance thresholds moved onto it; (3) the order of rules (#44) followed by every edit, with tests; (4) the setting and the fallbacks in the app; (5) the remaining thresholds named or removed. **Progress:** stage 1 done; stage 2 done (2026-11-26): `Tol::parallel_over` and `perpendicular_over` (the tolerance over a length, held between a sine of 1e-12 and 1e-3), `Plane::same_surface` judged over the faces' size (`Model::face_extent`), the cross-product parallel tests and the hand-written distances in primitives and cylinder bands on the tolerance, mesh import welding at the document's tolerance (or at the file's own precision, a millionth of its size, where that is coarser, and saying so). The fixed-angle `Tol::parallel` stays only where no length is at hand; stage 5 sweeps those. Curved-face layouts compare surface parameters (angles), not distances, so their "same node" rule is one named constant, not the tolerance. Stage 3 done (see #44). Stage 4 done (2026-11-26): File > Document Settings > Precision (Fine, Standard, Coarse, or Custom in millimetres); a new precision shows first what it would merge (points and lines closer or shorter than it, in every group) and is applied by a button as an undoable edit (`Command::SetPrecision`; it moves no geometry itself, what is closer merges when an edit next touches it); a line typed shorter than the precision cannot be drawn (it is one point) and the hint says so and points to Fine; geometry further than a billion tolerances from the origin (10 km at Standard) is flagged in Model Health's Scale row with the advice to move it or choose Coarse; a file opening at a precision other than Standard says so in the status bar. Stage 5 (2026-11-26, first sweep): named constants for what is not a geometry decision (`tol::GUARD` for raw divisors, `UNIT_GUARD` for products of unit directions, `NONZERO` for clamped divisors, `PARAM` for curve parameters; hand-written `1 - dot < 1e-9` tests use `ANGLE`); a taper's and a deform's span, a fillet's same-plane check and arcs lying in a plane (over their radius) now ask the tolerance; about 120 values named or moved, about 300 left, nearly all relative to a size already, parameter-space, guards, or display and screen allowances (not geometry). |
| 43 | Keeping the geometry rules current | Decided (owner, 2026-11-26) | **The written order of geometry rules (#42) is updated with every new tool that edits geometry, and whenever such a tool changes in a major way.** The update says which rules the tool relies on, which clean-up steps run after it and in what order, which tolerance (derived from the document's) it uses for each judgement, and what it may change that an earlier step decided (for example, whether it may harden a soft line). A chunk that adds or reworks such a tool is not finished until that is written down and tested. |
| 44 | The order of geometry rules | Decided (owner, 2026-11-26) | 1. **Exact tests first, with no tolerance:** which side of a plane, which way a loop turns. 2. **One tolerance, the document's (#42):** no step works out its own. 3. **After any edit, in this order:** weld points; split lines where they cross or touch; rebuild faces on each touched plane (the coplanar rule); cut curved faces by lines lying on them; remove duplicate faces; merge coplanar seams (Erase, booleans); soften seams between faces that meet smoothly; then what the user asked for directly (a line the user drew shows). 4. **What each step may change:** welding and splitting never change how a line looks (soft, hard, hidden) or which curve it belongs to; only the softening step makes a line soft, and only the user (drawing over it, Unsoften, Erase) makes a soft line hard; removing duplicates keeps the face the edit did not make; no step deletes a face another step just made, except a duplicate. 5. **Every tool that edits geometry says which steps it runs, in what order**, and tests the cases where one step would otherwise undo another (#43). The steps each edit runs today are listed in `docs/TOLERANCE-AUDIT.md` section 3. **Stage 3 (2026-11-26), made precise and tested** (`crates/prism-ops/tests/rule_order.rs`, one test per rule): splitting keeps a line's look and curve; a hard line *drawn across* a curve then parts it into two curves (its own step after splitting, as in SketchUp, brief 43), still keeping the look; where two lines weld into one, the softening rule decides the look (soft only where its faces meet smoothly), not whichever landed last; a line an edit adds over a soft line leaves it soft, a line the user draws over it shows; of two faces that became the same, the one the edit moved goes (a weld keeps the point that stayed put, `transform::weld_keeping`), and after Push/Pull and the curved-face rules the older face stays (an edit's faces are always the newer); a face drawn on another and the sides a pull makes survive the clean-up. **Fillet / Chamfer (2026-11-26, owner's session 22):** rounding first goes to the kernel as the solid is. If the kernel finds the size too large, near the ends of the rounded edges: lines between two faces of one plane (drawn on a face) are erased, and points where only two straight edges meet in line between the same two faces (where a line was once split) are joined, since the kernel takes each as a corner a round cannot pass. The edges are rounded, then the erased lines are drawn back with the ordinary splitting step (step 3), and any part of one left on no face (the round cut into its face) is removed. A line the user drew is kept wherever it still lies on the solid; a mere split point is not kept. **Widened the same day (sessions 24, Xby4):** also when the kernel cannot round them at all (not only too large); the lines taken off are those within the round's reach (its setback, with room) anywhere along the edges, not only at their ends; pieces of one rounded line are joined into one rounded edge; where the kernel still refuses, straight edges between flat faces that do not meet are rounded one by one by Prism's own round (a cylinder tangent to both faces), which also serves edges not on a closed solid (owner: two faces are all a round needs). If drawing the lines back would leave Model Health worse (an edge of three faces, a face inside), the round is refused instead. A line on a flat face (two faces of one plane) is not an edge to round. |
